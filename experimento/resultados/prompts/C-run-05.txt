## 1. Objetivo do sistema

O sistema permite que almoxarifes registrem entradas e saídas de produtos para controlar o saldo em estoque e identificar produtos abaixo do nível mínimo.

---

## 2. Escopo

### 2.1 Incluído

- Cadastro, consulta e listagem de produtos.
- Registro de movimentações de entrada e de saída.
- Consulta das movimentações de um produto.
- Consulta dos produtos com saldo abaixo do estoque mínimo.

### 2.2 Explicitamente excluído

O sistema **não** implementa:

- Autenticação, autorização ou controle de sessão.
- Interface web, HTML, CSS ou qualquer front-end.
- Persistência em disco, banco de dados, arquivos ou ORM.
- Exclusão ou alteração de produtos já cadastrados.
- Estorno, cancelamento ou alteração de movimentações.
- Fornecedores, pedidos de compra, preços ou valores financeiros.
- Múltiplos depósitos ou localização física dos produtos.
- Envio de e-mail, notificações ou mensageria.
- Paginação, ordenação configurável ou busca textual.
- Logging estruturado, métricas ou monitoramento.
- Docker, docker-compose, CI, Makefile ou scripts de deploy.
- Testes automatizados, README ou documentação adicional.

## 3. Glossário

| Termo | Definição |
|---|---|
| Produto | Item controlado pelo estoque, identificado por `id` próprio e por um `sku` único. |
| SKU | Código identificador do produto no estoque, com formato definido na Seção 5.1. |
| Saldo | Valor atual do campo `quantidade` de um produto. |
| Movimentação | Registro de entrada ou de saída de uma quantidade de um produto. Uma vez registrada, não é alterada nem cancelada. |
| Entrada | Movimentação que aumenta o saldo do produto. |
| Saída | Movimentação que diminui o saldo do produto. |
| Estoque mínimo | Valor do campo `estoque_minimo` do produto, abaixo do qual o produto é considerado em alerta. |
| Produto em alerta | Produto cujo `quantidade` é estritamente menor que seu `estoque_minimo`. |

## 5. Modelo de dados

### 5.1 Entidade: Produto

| Atributo | Tipo | Obrigatório | Restrições / validação | Exemplo |
|---|---|---|---|---|
| `id` | inteiro | Não (gerado pelo sistema) | Gerado pelo sistema, sequencial, iniciando em `1`, nunca reaproveitado | `1` |
| `nome` | string | Sim | Entre 1 e 100 caracteres, após remoção de espaços nas extremidades | `"Parafuso M6"` |
| `sku` | string | Sim | Exatamente 8 caracteres, contendo apenas letras maiúsculas de `A` a `Z` e dígitos de `0` a `9`; único no sistema | `"PARM6001"` |
| `estoque_minimo` | inteiro | Sim | Maior ou igual a `0` | `10` |
| `quantidade` | inteiro | Não (definido pelo sistema) | Maior ou igual a `0` | `0` |

**Valor inicial de `quantidade`:** `0`

### 5.2 Entidade: Movimentacao

| Atributo | Tipo | Obrigatório | Restrições / validação | Exemplo |
|---|---|---|---|---|
| `id` | inteiro | Não (gerado pelo sistema) | Gerado pelo sistema, sequencial, iniciando em `1`, nunca reaproveitado | `1` |
| `produto_id` | inteiro | Sim | Deve referenciar um `Produto` existente | `1` |
| `tipo` | string | Sim | Um de: `entrada`, `saida` | `"entrada"` |
| `quantidade` | inteiro | Sim | Estritamente maior que `0` | `50` |
| `data` | string | Não | Data no formato `AAAA-MM-DD`. Quando ausente, o sistema usa a data atual | `"2026-09-19"` |
| `saldo_apos` | inteiro | Não (calculado pelo sistema) | Saldo do produto após a aplicação desta movimentação | `50` |

**Estados possíveis de `tipo`:** `entrada`, `saida` · **não possui valor padrão: o campo é obrigatório**

## 6. Regras de negócio

| ID | Regra | Requisitos afetados |
|---|---|---|
| RN-01 | Uma movimentação de `tipo` igual a `entrada` soma sua `quantidade` ao `quantidade` do produto. | RF-04 |
| RN-02 | Uma movimentação de `tipo` igual a `saida` subtrai sua `quantidade` do `quantidade` do produto. | RF-05 |
| RN-03 | Uma movimentação de `tipo` igual a `saida` cuja `quantidade` seja maior que o `quantidade` atual do produto não pode ser registrada. | RF-05 |
| RN-04 | O campo `sku` é único entre todos os produtos cadastrados. | RF-01 |
| RN-05 | Um produto está em alerta quando seu `quantidade` é estritamente menor que seu `estoque_minimo`. | RF-07 |

## 7. Requisitos funcionais

### RF-01 — Cadastrar produto

- **Descrição:** O sistema deve cadastrar um novo produto no estoque.
- **Ator:** Almoxarife
- **Prioridade:** Must
- **Entrada:** `nome` (string), `sku` (string), `estoque_minimo` (inteiro)
- **Processamento:** validar os campos conforme a Seção 5.1; verificar RN-04; gerar `id` sequencial; definir `quantidade` como `0`.
- **Saída:** objeto `Produto` completo com status `201`.
- **Regras relacionadas:** RN-04
- **Critérios de aceitação:**
  - **CA-01.1** Dado um corpo válido com `nome`, `sku` inédito e `estoque_minimo`, quando `POST /produtos` for chamado, então a resposta deve ter status `201` e o corpo deve conter `id` inteiro, o mesmo `nome` enviado e `quantidade` igual a `0`.
  - **CA-01.2** Dado um corpo cujo `sku` possui 5 caracteres, quando `POST /produtos` for chamado, então a resposta deve ter status `422` e corpo `{"erro": "SKU inválido"}`.
  - **CA-01.3** Dado um `sku` já cadastrado em outro produto, quando `POST /produtos` for chamado, então a resposta deve ter status `409` e corpo `{"erro": "SKU já cadastrado"}`.
  - **CA-01.4** Dado um corpo cujo `estoque_minimo` é `-1`, quando `POST /produtos` for chamado, então a resposta deve ter status `422` e corpo `{"erro": "Dados inválidos"}`.

### RF-02 — Listar produtos

- **Descrição:** O sistema deve listar os produtos cadastrados.
- **Ator:** Almoxarife
- **Prioridade:** Must
- **Entrada:** nenhuma.
- **Processamento:** retornar todos os produtos cadastrados.
- **Saída:** lista de objetos `Produto` com status `200`.
- **Regras relacionadas:** nenhuma
- **Critérios de aceitação:**
  - **CA-02.1** Dado um estoque com ao menos um produto cadastrado, quando `GET /produtos` for chamado, então a resposta deve ter status `200`, o corpo deve ser uma lista JSON e deve conter um objeto cujo `id` é o do produto cadastrado.
  - **CA-02.2** Dado um produto cadastrado, quando `GET /produtos` for chamado, então o objeto correspondente na lista deve conter as chaves `id`, `nome`, `sku`, `estoque_minimo` e `quantidade`.

### RF-03 — Consultar produto por identificador

- **Descrição:** O sistema deve retornar os dados de um produto a partir do seu `id`.
- **Ator:** Almoxarife
- **Prioridade:** Must
- **Entrada:** `id` do produto no caminho da rota.
- **Processamento:** localizar o produto pelo `id`.
- **Saída:** objeto `Produto` com status `200`.
- **Regras relacionadas:** nenhuma
- **Critérios de aceitação:**
  - **CA-03.1** Dado um produto cadastrado, quando `GET /produtos/{id}` for chamado com o `id` desse produto, então a resposta deve ter status `200` e o corpo deve conter o mesmo `id` e o mesmo `sku` do produto cadastrado.
  - **CA-03.2** Dado um `id` que não corresponde a nenhum produto, quando `GET /produtos/{id}` for chamado, então a resposta deve ter status `404` e corpo `{"erro": "Produto não encontrado"}`.

### RF-04 — Registrar entrada de estoque

- **Descrição:** O sistema deve registrar uma movimentação de entrada, aumentando o saldo do produto.
- **Ator:** Almoxarife
- **Prioridade:** Must
- **Entrada:** `produto_id` (inteiro), `tipo` (string igual a `entrada`), `quantidade` (inteiro), `data` (string no formato `AAAA-MM-DD`, opcional)
- **Processamento:** localizar o produto; validar os campos conforme a Seção 5.2; aplicar RN-01; gerar `id` sequencial; registrar `saldo_apos` com o saldo resultante.
- **Saída:** objeto `Movimentacao` completo com status `201`.
- **Regras relacionadas:** RN-01
- **Critérios de aceitação:**
  - **CA-04.1** Dado um produto com `quantidade` igual a `0`, quando `POST /movimentacoes` for chamado com `tipo` igual a `entrada` e `quantidade` igual a `50`, então a resposta deve ter status `201` e o campo `saldo_apos` do corpo deve ser `50`.
  - **CA-04.2** Dada uma entrada de `50` unidades registrada com sucesso, quando `GET /produtos/{id}` for chamado, então o campo `quantidade` do produto deve ser `50`.
  - **CA-04.3** Dado um `produto_id` que não corresponde a nenhum produto, quando `POST /movimentacoes` for chamado, então a resposta deve ter status `404` e corpo `{"erro": "Produto não encontrado"}`.
  - **CA-04.4** Dado um corpo cuja `quantidade` é `0`, quando `POST /movimentacoes` for chamado, então a resposta deve ter status `422` e corpo `{"erro": "Dados inválidos"}`.
  - **CA-04.5** Dado um corpo cujo `tipo` é `transferencia`, quando `POST /movimentacoes` for chamado, então a resposta deve ter status `422` e corpo `{"erro": "Dados inválidos"}`.

### RF-05 — Registrar saída de estoque

- **Descrição:** O sistema deve registrar uma movimentação de saída, diminuindo o saldo do produto.
- **Ator:** Almoxarife
- **Prioridade:** Must
- **Entrada:** `produto_id` (inteiro), `tipo` (string igual a `saida`), `quantidade` (inteiro), `data` (string no formato `AAAA-MM-DD`, opcional)
- **Processamento:** localizar o produto; validar os campos conforme a Seção 5.2; verificar RN-03; aplicar RN-02; gerar `id` sequencial; registrar `saldo_apos` com o saldo resultante.
- **Saída:** objeto `Movimentacao` completo com status `201`.
- **Regras relacionadas:** RN-02, RN-03
- **Critérios de aceitação:**
  - **CA-05.1** Dado um produto com `quantidade` igual a `50`, quando `POST /movimentacoes` for chamado com `tipo` igual a `saida` e `quantidade` igual a `20`, então a resposta deve ter status `201` e o campo `saldo_apos` do corpo deve ser `30`.
  - **CA-05.2** Dada uma saída de `20` unidades registrada com sucesso sobre saldo de `50`, quando `GET /produtos/{id}` for chamado, então o campo `quantidade` do produto deve ser `30`.
  - **CA-05.3** Dado um produto com `quantidade` igual a `50`, quando `POST /movimentacoes` for chamado com `tipo` igual a `saida` e `quantidade` igual a `51`, então a resposta deve ter status `409` e corpo `{"erro": "Quantidade insuficiente em estoque"}`.
  - **CA-05.4** Dado um produto com `quantidade` igual a `50`, quando `POST /movimentacoes` for chamado com `tipo` igual a `saida` e `quantidade` igual a `50`, então a resposta deve ter status `201` e o campo `saldo_apos` do corpo deve ser `0`.

### RF-06 — Listar movimentações de um produto

- **Descrição:** O sistema deve listar as movimentações de um produto.
- **Ator:** Almoxarife
- **Prioridade:** Should
- **Entrada:** `id` do produto no caminho da rota; parâmetro de consulta opcional `tipo`, com valores aceitos `entrada` ou `saida`.
- **Processamento:** localizar o produto; quando `tipo` for informado, retornar apenas as movimentações do produto cujo `tipo` seja igual ao informado; quando ausente, retornar todas as movimentações do produto.
- **Saída:** lista de objetos `Movimentacao` com status `200`.
- **Regras relacionadas:** nenhuma
- **Critérios de aceitação:**
  - **CA-06.1** Dado um produto com uma entrada registrada, quando `GET /produtos/{id}/movimentacoes` for chamado, então a resposta deve ter status `200`, o corpo deve ser uma lista JSON e deve conter um objeto cujo `id` é o da movimentação registrada.
  - **CA-06.2** Dado um produto com uma entrada e uma saída registradas, quando `GET /produtos/{id}/movimentacoes?tipo=saida` for chamado, então a resposta deve ter status `200` e todos os objetos da lista devem ter `tipo` igual a `saida`.
  - **CA-06.3** Dado um `id` que não corresponde a nenhum produto, quando `GET /produtos/{id}/movimentacoes` for chamado, então a resposta deve ter status `404` e corpo `{"erro": "Produto não encontrado"}`.

### RF-07 — Consultar produtos em alerta de estoque mínimo

- **Descrição:** O sistema deve listar os produtos cujo saldo está abaixo do estoque mínimo.
- **Ator:** Almoxarife
- **Prioridade:** Must
- **Entrada:** nenhuma.
- **Processamento:** aplicar RN-05 a todos os produtos cadastrados e retornar os que estiverem em alerta.
- **Saída:** lista de objetos `Produto` com status `200`.
- **Regras relacionadas:** RN-05
- **Critérios de aceitação:**
  - **CA-07.1** Dado um produto com `estoque_minimo` igual a `10` e `quantidade` igual a `0`, quando `GET /alertas` for chamado, então a resposta deve ter status `200` e a lista deve conter um objeto cujo `id` é o desse produto.
  - **CA-07.2** Dado um produto com `estoque_minimo` igual a `10` e `quantidade` igual a `20`, quando `GET /alertas` for chamado, então a lista não deve conter nenhum objeto cujo `id` seja o desse produto.
  - **CA-07.3** Dado um produto com `estoque_minimo` igual a `10` e `quantidade` igual a `10`, quando `GET /alertas` for chamado, então a lista não deve conter nenhum objeto cujo `id` seja o desse produto.

## 8. Contratos de interface

Todas as rotas usam o prefixo raiz `/`, sem versionamento e sem prefixo adicional.

### 8.1 `POST /produtos`

- **Requisito:** RF-01
- **Corpo da requisição (JSON exato):**

```json
{
  "nome": "Parafuso M6",
  "sku": "PARM6001",
  "estoque_minimo": 10
}
```

- **Resposta de sucesso — status `201`:**

```json
{
  "id": 1,
  "nome": "Parafuso M6",
  "sku": "PARM6001",
  "estoque_minimo": 10,
  "quantidade": 0
}
```

- **Respostas de erro:**

| Status | Condição | Corpo exato |
|---|---|---|
| `422` | `sku` não satisfaz a validação da Seção 5.1 | `{"erro": "SKU inválido"}` |
| `422` | `nome` ou `estoque_minimo` inválido, ausente ou de tipo incorreto | `{"erro": "Dados inválidos"}` |
| `409` | `sku` já cadastrado (RN-04) | `{"erro": "SKU já cadastrado"}` |

### 8.2 `GET /produtos`

- **Requisito:** RF-02
- **Corpo da requisição:** nenhum
- **Resposta de sucesso — status `200`:** lista de objetos `Produto`, cada um idêntico em formato ao retornado por `POST /produtos`.
- **Respostas de erro:** nenhuma.

Quando não houver produto algum, a resposta é status `200` com corpo `[]`.

### 8.3 `GET /produtos/{id}`

- **Requisito:** RF-03
- **Corpo da requisição:** nenhum
- **Resposta de sucesso — status `200`:** objeto `Produto`.
- **Respostas de erro:**

| Status | Condição | Corpo exato |
|---|---|---|
| `404` | `id` não corresponde a nenhum produto | `{"erro": "Produto não encontrado"}` |

### 8.4 `POST /movimentacoes`

- **Requisitos:** RF-04 e RF-05
- **Corpo da requisição (JSON exato):**

```json
{
  "produto_id": 1,
  "tipo": "entrada",
  "quantidade": 50,
  "data": "2026-09-19"
}
```

O campo `data` é opcional; quando ausente, o sistema usa a data atual.

- **Resposta de sucesso — status `201`:**

```json
{
  "id": 1,
  "produto_id": 1,
  "tipo": "entrada",
  "quantidade": 50,
  "data": "2026-09-19",
  "saldo_apos": 50
}
```

- **Respostas de erro:**

| Status | Condição | Corpo exato |
|---|---|---|
| `422` | corpo malformado, campo ausente, de tipo incorreto, `tipo` fora dos valores aceitos ou `quantidade` menor ou igual a `0` | `{"erro": "Dados inválidos"}` |
| `404` | `produto_id` não corresponde a nenhum produto | `{"erro": "Produto não encontrado"}` |
| `409` | saída com `quantidade` maior que o saldo do produto (RN-03) | `{"erro": "Quantidade insuficiente em estoque"}` |

### 8.5 `GET /produtos/{id}/movimentacoes`

- **Requisito:** RF-06
- **Parâmetro de consulta:** `tipo` (opcional), valores aceitos `entrada` ou `saida`
- **Corpo da requisição:** nenhum
- **Resposta de sucesso — status `200`:** lista de objetos `Movimentacao`.
- **Respostas de erro:**

| Status | Condição | Corpo exato |

| `404` | `id` não corresponde a nenhum produto | `{"erro": "Produto não encontrado"}` |

### 8.6 `GET /alertas`

- **Requisito:** RF-07
- **Corpo da requisição:** nenhum

- **Respostas de erro:** nenhuma.

## 10. Tratamento de erros (padrão global)

- **Formato único de resposta de erro:**

```json
{
  "erro": "mensagem exata definida na Seção 8"
}
```

O objeto de erro possui **exatamente uma chave**, chamada `erro`, cujo valor é uma string. Nenhuma resposta de erro pode usar a chave `detail`, `message`, `error` ou qualquer outra.

- **Tabela de status HTTP e seu significado neste sistema:**

| Status | Uso neste sistema |
|---|---|
| `200` | Consulta ou listagem realizada com sucesso |
| `201` | Recurso criado com sucesso |
| `404` | Recurso referenciado por identificador não existe |
| `409` | Conflito com o estado atual do sistema (duplicidade ou saldo insuficiente) |
| `422` | Dados de entrada inválidos |

- **Precedência de validação:** quando mais de uma condição de erro se aplica à mesma requisição, o sistema retorna o erro de maior precedência, na ordem abaixo:

  1. Corpo malformado, campo obrigatório ausente, de tipo incorreto ou com valor fora do permitido → `422`
  2. Parâmetro de consulta com valor fora dos aceitos → `422`
  3. Recurso referenciado por identificador não existe → `404`
  4. Violação de regra de negócio relativa ao saldo ou à duplicidade → `409`

  Dentro do item 1, as validações de formato que possuem mensagem própria têm precedência sobre a mensagem genérica `Dados inválidos`: um `sku` presente e do tipo string, mas que não satisfaça a validação da Seção 5.1, retorna `{"erro": "SKU inválido"}`.
